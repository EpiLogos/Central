# Experimental development

Oriented by [docs-methodology](../docs-methodology/SKILL.md). A composable
path, not mandatory stages: skip a step whose layer is not actually touched,
and say that you skipped it.

```text
authored question → bounded source horizon → Design/Mockup/Architecture candidate → prototype/implementation → evidence → returned understanding → source proposal
```

**Entry.** There is an explicit question (from the human or a Wayfinder frontier) whose answer is not known and is cheaper to learn by building.

**Near-miss.** The answer is already determined (product-development); the question is only about wording (no prototype needed).

## Composes

- **authored question** — write the question down with its owner before building
- **bounded source horizon** — read only the documents the question touches; use the inventory
- **Design/Mockup/Architecture candidate** — the matching form Skill, marked `agent-inference` and experimental
- **prototype/implementation** — throwaway unless promoted; the locally adopted `prototype` Method where carried
- **evidence** — what the prototype showed, dated
- **returned understanding** — what was learned, including negative results
- **source proposal** — a proposal to the owning document; never a silent edit

Retrieve with the compact inventory and a Jev attention question before
loading document bodies ([docs-methodology](../docs-methodology/SKILL.md#attention-and-retrieval)).
Agent-authored Vision, Design, Mockup or Architecture candidates stay at
`agent-inference` standing until a human recognises them.

## Verification

The question is answered, or recorded as unanswered with why; the prototype is either retired or explicitly proposed for promotion.

## Return

Understanding to the Wiki; any source change as a proposal to its owner.
