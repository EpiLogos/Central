# Central — public framing handoff

**Status:** outward-copy source for Central #71  
**Use:** O:I/site and adjacent product descriptions  
**Authority:** product framing derived from current Central vision and the O:I founding positions; not evidence of unmerged/local acceptance

## The human reason first

Central gives a person a durable authored ground for the parts of their technological world they most need to remain responsible for, while Agents and other software maintain changing knowledge and machinery around that ground.

The useful consequence is attentional rather than clerical. More capable Agent systems should not require a person to spend more time restating context, supervising reversible implementation choices and reconstructing state. The surrounding system should recover what is already known and return human attention toward purpose, experience, judgement, consequential choice and Recognition of what reality has produced.

Do not reduce this to “personal context for AI” or “a filesystem for prompts”. The authored ground matters because it remains an inspectable human source even when the current Agent, model, interface or index changes.

## A concise public relation

```text
write the things you actually want to remain responsible for
        ↓
keep them in ordinary source you own
        ↓
let Agents maintain navigable knowledge around those sources
        ↓
develop against the real Project and gather evidence
        ↓
return material differences to human judgement
        ↓
renew authored ground only when something is actually worth changing
```

The human does not have to maintain a generated mirror of current code. Agent knowledge can change rapidly as implementation changes; authored ground can remain sparse and high-signal.

## Start where you already are

Existing Projects and ordinary files remain real.

ProjectCentral is an optional Project-local relation, not a documentation adoption gate. A mature Project can retain a native vision, design corpus or README in place and explicitly relate it as human source. A small Project can begin with one note or with no authored ground yet. A fresh Project can use the same space for more substantial visioning when that is genuinely missing.

The bootstrap promise is therefore:

> recover before asking; author only what is actually missing.

## Human source and Agent knowledge are complementary

```text
ProjectCentral/user/**
    human-owned authorship aperture

ProjectCentral/agents/wiki/**
    Agent-maintained knowledge about/across the Project
```

Location does not magically confer authorship. Generated suggestions can help a person write or think without silently becoming human-authored source.

The distinction exists so Agents can learn current reality aggressively while the Project still retains a durable answer to a different question: what was meant, wanted, valued or deliberately adopted?

## Returned reality is allowed to change the vision

Central does not freeze human intent above implementation.

A Project can return evidence that the implementation is wrong, the design should develop, the original intention needs refinement, or nothing important should change. What matters is that those differences remain legible before one source class is rewritten as another.

```text
vision tells us what is meant
code tells us what exists now
evidence tells us what happened
Agent synthesis relates them
human authorship decides what renewed human ground should say
```

This is how a Project can learn without treating the latest generated account as its new telos.

## Commission and Recognition

Where the wider Software Factory relation is useful, Central supports two high-energy human apertures without owning Factory semantics:

- **Commission:** an authored direction, existing source or sufficiently determinate request makes the work worth undertaking.
- **Recognition:** returned reality becomes consequential enough for the human to accept, redirect, reject or develop the direction.

Between those moments, Agents and deterministic systems should carry as much source recovery, implementation, testing, evidence gathering and routine reversible judgement as existing authority permits.

Do not present Recognition as approval of every technical completion.

## Objective Internality

Central supplies one concrete form of Objective Internality: part of an actor's operative interior can live in objective, inspectable structures outside a single prompt or model invocation.

The useful design move is not to put everything into one memory/profile object. Different exteriorised structures keep different authority:

```text
human-authored ground
Agent-maintained knowledge
observed reality
derived/indexed state
Projection/public presentation
```

They become more useful by being mutually legible, not by becoming the same thing.

## Projection / public world

Central remains source. O:I owns selective WorldPresentation/Projection.

```text
Central source
    ↓ selected reading
WorldPresentation
    ↓ explicit ratification
Projection
```

Local O:I can operate over a richer private reading than public Explore. Source existence, Agent readability, retrieval, local presentation, Projection selection and public hosting remain different states.

A browser/public refinement changes the Projection representation. It does not silently rewrite Central source. A durable return to human source remains an explicit proposal/review/adoption relation.

## Current status language

Safe current claims on the Central #70/#71 development line include:

- ProjectCentral has a recursive human-source / Agent-Wiki filesystem and identity contract;
- authored-ground inspection can distinguish empty/partial/established state;
- native sources can be retained in place with explicit provenance/standing relations;
- generated, observed, inferred and human-authored/adopted standings remain distinguishable;
- AIKit has merged its ProjectCentral KnowledgeApplication/Wiki-maintenance consumer and preserves those distinctions;
- account/HTML/Projection remain readings/renderers, not source.

Do **not** yet describe the full physical `Central → AIKit → Factory → O:I Explore` return loop as owner-workstation accepted. Factory #155 and O:I #85 reserve that proof for the same genuine local Project, and Central #70/PR #73 remains draft until that wider acceptance is reconciled.

## Short public-copy seed

Central is the part of O:I you keep.

It gives you ordinary files for the intentions, preferences and Project ground you actually want to carry forward, while Agents maintain an evolving knowledge world around them. Existing Projects stay where they are. The system can recover what is already known, follow implementation and evidence as they change, and return meaningful differences without quietly rewriting what you meant. The aim is less repeated context repair and technical babysitting, and more room for the human work that remains genuinely yours: purpose, experience, judgement and Recognition.
