# Session work has a place

**Status:** distributed default — becomes human source on adoption

Work that has nowhere to land lands everywhere. I have watched a session end and leave its thinking scattered across the Work root — dated folders, draft files, half-named remains — because no field owned the session's current horizon. The Work root is an index of projects, not a scratchpad, and a loose folder there is a placement fault, not a style choice.

Every session that works in my world stands in one of two registers, and each register keeps a NOW field for exactly this:

```text
project session        Work/<Name>/ProjectCentral/now/agents/     via projectcentral.now.*
root / cross-project   Control/agents/now/agents/                 root register, Control-structure law
```

Cross-project, suite-level and world-keeping work — anything that is not inside one project's own concern — belongs to the root field, not to the first project folder it happened to start from. Work inside a project's concern belongs to that project's field, even when the session was started elsewhere.

A session return is bounded and attributed: what was done, what it means, what remains open, where the durable evidence lives. It is not a transcript and not a report that pretends to be source. Durable material — a learning, a decision, a convention — does not stay in NOW; it returns to its owner through the promotion path, and NOW keeps only the ref.

A dated folder at the Work root, a draft file parked beside the projects, an outcome that lives only in a finished chat: each of these is the same fault — a horizon with no field. When you find one, account for it in the NOW field of its register and propose its placement; do not move it silently, and do not add to it.

The horizon stays recoverable so the next session — or I — can pick up the work without the conversation that started it.
